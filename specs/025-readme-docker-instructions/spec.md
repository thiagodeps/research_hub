# Feature Specification: readme-docker-instructions

**Feature Branch**: `[025-readme-docker-instructions]`  
**Created**: 2026-09-09  
**Status**: Draft  
**Input**: User description: "ajuste o read me , com instruçoes claras de como rodar , usando o docker para gerar a imagem com os downloads ensinando nos 3 metodos como base"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Update Build and Run Instructions (Priority: P1)

As a developer or user compiling the app via Docker, I want clear instructions in the README on how to run the generated artifacts (AppImage, .deb, .rpm) so that I can easily test or install the application on Linux.

**Why this priority**: Users need to know what to do with the artifacts generated by `make docker-bundle`.

**Independent Test**: Can be tested by reading the README and following the provided commands.

**Acceptance Scenarios**:

1. **Given** a user has run `make docker-bundle`, **When** they look at the README, **Then** they see instructions for running the AppImage, installing the .deb, and installing the .rpm.

### Edge Cases

- What happens when a user doesn't have root access? (They can use the AppImage method after changing ownership).

## Requirements *(mandatory)*

### Technical & Architectural Constraints

- **CON-001**: A aplicação DEVE ser um app desktop de processo único em Tauri 2.0.
- **CON-002**: A persistência DEVE usar SQLite em arquivo único, embarcado.
- **CON-003**: Toda regra de negócio DEVE residir no processo Rust.
- **CON-004**: Todas as entidades do domínio exigem CRUD completo operado unicamente por perfil de Admin.
- **CON-005**: Paridade funcional precede melhoria. 
- **CON-006**: Alvos de release são Linux e Windows.

### Functional Requirements

- **FR-001**: System MUST document how to run the `.AppImage` generated by Docker.
- **FR-002**: System MUST document how to install the `.deb` package generated by Docker.
- **FR-003**: System MUST document how to install the `.rpm` package generated by Docker.
- **FR-004**: System MUST instruct the user to change ownership of the AppImage since Docker creates it as root.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: The README contains 3 distinct methods for running/installing the Linux artifacts.
- **SC-002**: Commands provided in the README are copy-pasteable and correct.

## Assumptions

- Users running `make docker-bundle` are on a Linux host (or WSL) and have basic terminal knowledge.
- The artifacts are generated in the `dist/` directory.
